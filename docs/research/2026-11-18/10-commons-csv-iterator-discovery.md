# R144 · Finding iterator state in Apache Commons CSV

Rust started with five public operations and located the parser's shared iterator, its pending record, the record counter, and the path from parser closure to the underlying reader. The reviewer’s forecast on the delivered packet matched **all 36 observed values**. It gave exact source locations for **20 of 22 citations**. Two correct quotations pointed one line too early, so the full check failed. Calling `hasNext()` for the first time advanced the parser's record count before the caller consumed a record. Closing the parser after that lookahead made the pending record inaccessible. ## What the real parser did

Each history started with a fresh parser over two records, `oak` and `elm`. The evaluator obtained handles A and B from separate calls to `iterator()`. They were the same Java object in every run. The record number started at zero. The table includes the count after each operation.

| History | Return values paired with the parser record count |
| --- | --- |
| A looks ahead twice, B consumes, A consumes, B looks ahead and tries to consume | `true / 1`, `true / 1`, `oak / 1`, `elm / 2`, `false / 2`, `NoSuchElementException / 2` |
| B consumes, A and B look ahead, B consumes, A tries to consume | `oak / 1`, `true / 2`, `true / 2`, `elm / 2`, `NoSuchElementException / 2` |
| A looks ahead, the parser closes, B looks ahead, A tries to consume | `true / 1`, `closed / 1`, `false / 1`, `NoSuchElementException / 1` |

The parser returns its existing iterator at `CSVParser.java:905`. The iterator fills its pending record during lookahead at lines 267–268. Reading another record increments the parser counter at line 954. The iterator checks whether the parser is closed before returning even a pending record. The parser delegates that check to the lexer at line 867, and the lexer asks its reader at `Lexer.java:135`. The JVM observer compiled the actual production sources with JDK 21.0.12.1 and the pinned Commons IO 2.22.0 JAR, then exercised only public methods. ## Where the source evidence stops

The packet showed `this.recordNumber = builder.recordNumber - 1` at `CSVParser.java:531`. It omitted the builder field initialized to `1` at line 161. Likewise it showed the copied row limit but omitted the default format and its builder's initial row limit. The independent Java run supplied a reliable starting count. A reviewer relying on this packet alone would need to qualify its inference about the initial count. The same distinction matters for a future solver input because an assumed starting state can make all later counts appear consistent. [Initialization audit with exact source lines](D:/BuildArtifacts/lesscode/corrective-audit/task70/initialization-audit.json)

**Revise the evidence extraction.** The reviewer explicitly identified both defaults as assumptions. The next experiment should follow those initializer references and challenge them by changing a default in a disposable copy. Have Rust resolve quoted source locations and flag ambiguous or missing matches. Keep the R144 results frozen. This case supports cross-file source selection from a public API and a behavioral forecast on one separately selected specimen. It leaves general discovery and consolidation open.
