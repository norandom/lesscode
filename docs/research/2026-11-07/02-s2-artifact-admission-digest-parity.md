## Conclusion first
S2 succeeded technically and failed the frozen effort budget:

1. **Artifact admission (U1 inputs)**: all five E4 golden/held-out/smoke artifacts verify
   against committed and local sidecars (bytes as stored AND declared LF-body digests).
   All six E4 regenerator turn files verify. The six T4 turn files do NOT: five bytes
   mismatch their committed sidecars and `t4-turn1/response.json` is missing. T4 turn
   evidence is therefore inadmissible as bound; U6 turn checks proceed on the verified
   E4 turns (accepted turn 3, failed turn 1 thinking-only, failed turn 2 `labeled_reason`),
   which cover accepted and failed turns. The four specimen SQLite files are present with
   no committed sidecar (unbound-local class, as the plan froze).
2. **Digest parity (U2/U6 prerequisite) PROVEN on real artifacts**: a new Rust module
   (`native/src/pyjson.rs`, order- and token-preserving JSON model + Python `json.dumps`
   writer incl. `-0.0`/`0.0`, `1e+16`/`1e-07` repr rules, `ensure_ascii` escapes with
   surrogate pairs, arbitrary-precision ints, `NaN`/`Infinity`, `indent=0/1` shapes)
   re-emits the frozen 5,643,360-byte E4 golden and held-out traces byte-identically and
   reproduces the recorders' declared LF-body digests. Verified by `golden_e4_trace_digest_parity`
   (nextest run 76023a7d-91c0-44f0-b6d9-27728e97072f, 109/109 passed) against pinned
   Python-generated fixtures and the sidecar-declared identities.
3. **U7 OVERRUN**: attempt-1 charged lines already total **774** (`pyjson.rs` 463 +
   `admission.rs` 293 + `lib.rs` +2 + `main.rs` +16 registration hooks, rustfmt canonical)
   against the frozen ≤600 cumulative budget, before any S10 shared Python runner and
   adapters (projected further 250–450). The audit's assumption that digest parity would
   be a thin `serde_json` formatter was wrong: byte parity requires an order/token-preserving
   model because `serde_json::Value` cannot preserve insertion order or Python float/int
   tokens without feature changes that would alter existing behavior.
