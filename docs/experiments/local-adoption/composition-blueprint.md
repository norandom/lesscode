# COBESY composition blueprint: field baselines and a rejected shortcut

## Intake and framing

- Audience: the project owner and agents using Lesscode in a real codebase.
- Target behavior: admit one complete responsibility and test a concrete existing
  capability against its behavior before claiming source reduction.
- Governing message: field measurements are now repeatable; compression remains
  an empirical claim requiring a useful whole replacement and preserved behavior.
- Working assumption, not a diagnosed culture: visible activity, small files and
  green CI can be mistaken for progress toward less code. Frame failed hypotheses
  as useful findings; impose no deletion quota and do not blame code authors.
- Safety/accountability: the owner's request supports a learning-oriented framing.
  No team psychological-safety score is inferred from a repository.
- Disproof: reject an apparent shortcut on a routing mismatch, lost safeguard,
  exported complexity or non-beneficial complete replacement. Withhold metrics
  when the parser fails a representative syntax check.
- Adoption anchor: the owner and the local OpenCode agent. Point-of-action aid:
  the installed skill reference. No organization-wide rollout is proposed.

Lead with the decision and evidence, not a tool-installation chronology. The
opening conflict is concrete: the owner wants less maintained code, but neither
CI nor short functions establishes it. Keep command detail in the linked job aid.
Separate observed counts, interpretations, failed probes and untested proposals.

## Experiment continuity

This round follows the earlier native comparison/self-application work; it is
not another successful compression trial. Record two specimen baselines, one
finite replacement-feasibility probe, zero whole rewrites and zero adoptions.
The 11 cases and repeated scans are not independent experiments. Preserve the
Lizard failure and snapshot byte-drift event beside the admitted measurements.

For a later results article, replace the final row with actual paired behavior,
whole-scope production/test/support deltas and adoption disposition. Do not imply
maintenance-effort savings until a change exercise measures them. Human-facing
prose should use ordinary names, concrete operations and precise limits.

## Validation

The sequence distinguishes purpose, measurement, validity, behavior and next
decision. The report leads with the conclusion, details sit behind links, and
the installed skill provides the job aid in the working project. Disproof
conditions and no-change outcomes are explicit. No broadcast/change campaign is
needed for this local pilot. This is a composition blueprint, not a drafted article.
