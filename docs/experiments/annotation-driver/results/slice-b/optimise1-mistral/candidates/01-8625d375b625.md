# Pack authoring guide, version 3

This is for mutation testing, the software testing technique that measures
how well a project's own test suite detects small deliberate changes to its
code. Each changed copy is run only against that project's tests in an
isolated checkout and is then discarded; nothing is deployed or executed
elsewhere. The tool that makes the changes is called the mutation engine.

The mutation engine reads one small JSON data pack per programming language.
The engine itself knows no language. It parses source files with the
tree-sitter grammar that ast-grep ships for the language, finds syntax nodes
the pack names, and rewrites them with the templates the pack gives. You
write the pack for one language. You are given packs for other languages as
examples of the format, not as content to copy: node kind names differ
between grammars.

Name source and validity. Before writing the JSON, inspect the tree-sitter
grammar that ast-grep ships for the target language and treat its node-type
table as the only authority for node kind names, field names, and operator
tokens. Copy each identifier exactly as printed in that table. Do not coin a
kind name by turning a construct's role into an identifier, do not import
names from another language's pack, and do not keep a plausible name that is
absent from the table: one unknown node kind makes the whole pack invalid.
The same rule applies to every field name in `kinds.branch_condition.field_of`
and to every token in `token_swaps` and `negation_swaps`. Some grammars fold
several surface forms into one named node, split one construct across several
nodes, expose only an anonymous token, or have no named node for a construct;
in those cases list the named nodes that actually exist, each once, and omit
what has no named node instead of inventing one.

## Fields

Every node kind below must be an exact named node type of the target grammar.
A name that does not exist in that grammar makes the whole pack invalid.

| Field | Meaning |
| --- | --- |
| `language` | The language name as ast-grep spells it, lower case |
| `comment_kinds` | Named node kinds of comments. Nothing inside them is ever touched |
| `string_kinds` | Named node kinds of string literals, including multi-part or template strings only when the grammar has separate named kinds for those forms. List a kind once even when it covers several surface forms |
| `unwrap_kinds` | Named node kinds of a parenthesis wrapper that belongs to a statement's syntax, as in a condition that is syntactically wrapped. When a condition is such a wrapper, the engine works on the expression inside it. Empty when conditions are not wrapped or the wrapper has no named node |
| `test_attribute_markers` | Text fragments of attributes or annotations that mark test-only code inside a production file. Empty when the language keeps tests in separate files |
| `test_attribute_kinds` | Named node kinds of the attribute or annotation items that can stand directly in front of a declaration and carry one of the `test_attribute_markers`. Required when `test_attribute_markers` is not empty; leave it out otherwise |
| `kinds.branch_condition.field_of` | Pairs `[statement kind, field name]` using the exact node kind and the exact grammar field name: the named field of that statement kind holds a condition that decides control flow. List only the conditional and loop statements and conditional expressions whose grammar rule actually has such a field |
| `kinds.branch_condition.returned` | `{"of", "kinds", "tokens"}`: `of` lists the named node kinds of a return; `kinds` the named node kinds of logical, comparison and negation expressions; `tokens` the operator tokens that make such an expression a yes-or-no value. A returned expression of one of these kinds with one of these operators is a condition |
| `kinds.failure_state.nodes` | Named node kinds that signal failure to the caller: raising or throwing, returning, propagating an error |
| `kinds.failure_state.nodes_with_prefix` | Optional. Named node kind mapped to text prefixes, for failure signals that are ordinary calls or macros in this language and can only be told apart by how they begin |
| `kinds.error_order.nodes` | The named node kind of a conditional statement that can directly follow another one of the same kind. Always with `"requires_next_sibling": true` |
| `kinds.state_write.nodes` | Named node kinds of assignments and in-place updates |
| `kinds.state_write.call_statements` | Named node kinds of a call, and of an awaited call where the language has one, that can stand alone as a statement. Such a statement counts as a write made through a call |
| `kinds.pure_shell_boundary.nodes` | Named node kinds of function and method definitions |
| `noop_statement` | Text of a statement that does nothing and is valid wherever a statement may stand |
| `statement_wrappers` | Named node kinds that wrap an expression to make it a statement of its own |
| `statement_terminator` | The token that ends a simple statement, if the language has one; leave it out otherwise |

## Operators

`operators` tells the engine how to rewrite a site. Templates may use
`{text}` (the node's text), `{noop}` (the `noop_statement`) and `{child0}`
(the text of the node's first named child). Operator tokens must be spelled
exactly as they appear in the target language and its grammar.

| Entry | Meaning |
| --- | --- |
| `operators.branch_condition.template` | Replaces a condition by its logical negation. The result must be valid syntax in the place where the condition stood, for any condition expression |
| `operators.branch_condition.token_swaps` | Pairs of operator tokens that can replace each other without changing the type of the expression: equal and not equal, a strict and a non-strict comparison, logical and and or. Spell them exactly as the language does |
| `operators.branch_condition.negation_swaps` | The pairs among `token_swaps` whose swap gives exactly the logical negation of the comparison: equal and not equal, in every spelling the language has. The engine uses it to avoid producing the same change twice. Do not list a strict and a non-strict comparison, or and and or |
| `operators.branch_condition.exclude_kinds` | Optional. Named node kinds that can appear in a condition position but cannot be negated by the template, such as a pattern-binding condition or an empty condition |
| `operators.failure_state.by_kind` | Named node kind mapped to a replacement template that removes the failure. Use `{noop}` for a statement that can simply be dropped. Leave out kinds for which no replacement is valid in general, such as returning a value |
| `operators.failure_state.returned_literal_swaps` | Pairs of literals that can replace each other as a returned value: the two boolean literals, and 0 and 1 |
| `operators.state_write` | Always `{"statement": "{noop}"}`: a write that is a statement of its own is replaced by the empty statement |
| `operators.error_order` | Always `{"swap_next": true}` |

## Rules

- Verify every node kind, field name, and operator token against the target
  grammar's node-type table before returning. Precision matters more than
  coverage: a wrong kind produces changes that do not parse or do not compile,
  and an unknown kind invalidates the pack.
- If a construct is not represented by a named node in that grammar, or has
  no valid general replacement, omit it. Do not add a kind just to make the
  pack look complete.
- Do not include anything specific to a particular project, library or file.
- Keep the pack small: at most 40 lines and 2,500 characters, formatted like
  the examples.

## Output

Return only the JSON object of the pack, with no text before or after it.
